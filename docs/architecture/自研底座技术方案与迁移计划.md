# 自研底座技术方案与迁移计划

版本：v0.1  
日期：2026-07-10  
适用范围：成果计划系统第一阶段基础功能、第二阶段 AI 辅助能力

## 1. 决策结论

成果计划系统停止继续深度依赖若依二开，改为自研轻量企业应用底座。

若依项目保留为参考代码，不删除、不回滚、不作为主工程继续演进。新主工程为：

```text
代码/planning-platform
```

## 2. 变更原因

### 2.1 当前问题

1. 若依多个模块存在“禁用/参考官网开启”的产品约束，后续可能被商业开关或外部文档流程卡住。
2. 旧底座保留大量与成果计划无关的菜单、模块和依赖，首版业务容易被框架噪音干扰。
3. 成果计划系统最核心的是组织权限、计划成果闭环、审计和 AI 辅助，不需要完整承接若依全部生态。

### 2.2 新路线目标

1. 代码完全可控，业务边界清晰。
2. 只保留本项目真正需要的底座能力。
3. 支持 PC 管理端、App、微信小程序多端同构。
4. 第二阶段 AI 由自研适配层接入，不依赖若依或 JEECG 的 AI 模块。

## 3. 参考对象

JEECG 的公开产品形态可作为参考：它强调 Spring Boot 后端、Vue/Ant Design Vue 前端、Online 表单、代码生成、报表、流程和移动端能力。我们只借鉴产品能力组织方式，不依赖其代码和商业模块。

参考来源：

1. JEECG 官网：https://www.jeecg.com/
2. JEECG Boot 仓库：https://github.com/jeecgboot/JeecgBoot

## 4. 自研底座定位

一句话定位：

> 为成果计划系统自研一个可控的企业管理底座，支撑账号登录、组织权限、菜单权限、数据权限、审计日志、OSS 文件、计划成果业务和 AI 辅助能力，避免被第三方底座的商业模块和无关业务牵制。

## 5. 技术栈

### 5.1 后端

| 类型 | 选型 |
| --- | --- |
| 语言 | Java 17 |
| 框架 | Spring Boot 3.x |
| 安全 | Spring Security + JWT + Redis 会话 |
| ORM | MyBatis-Plus |
| 数据库 | MySQL 8.x |
| 缓存 | Redis |
| 接口文档 | Knife4j / Springdoc OpenAPI |
| 文件 | 阿里云 OSS |
| 短信 | 阿里云短信服务 |
| 日志 | 登录日志、操作日志、审计日志 |
| 部署 | Docker Compose 单机优先，后续可拆服务 |

### 5.2 PC 管理端

| 类型 | 选型 |
| --- | --- |
| 框架 | Vue3 + Vite + TypeScript |
| UI | Element Plus |
| 状态 | Pinia |
| HTTP | Axios |
| 权限 | 动态菜单 + 路由守卫 + 按钮权限指令 |

说明：JEECG 常用 Ant Design Vue，但本项目之前已围绕 Element Plus 做过若依页面，团队上手成本更低，因此自研底座 PC 端优先采用 Element Plus。

### 5.3 App/微信小程序

| 类型 | 选型 |
| --- | --- |
| 框架 | uni-app + Vue3 + TypeScript |
| UI | Wot Design Uni |
| 状态 | Pinia |
| 端 | App、微信小程序、H5 调试 |

## 7. 底座能力分层

### 7.1 P0 必须先做

| 能力 | 说明 |
| --- | --- |
| 登录认证 | 账号密码登录，JWT，Redis 会话，退出登录，刷新 Token |
| 用户管理 | 超级管理员创建员工账号，手机号必填，随机初始密码 |
| 组织管理 | 部门、项目组、上下级、项目经理、部门负责人 |
| 角色权限 | 菜单权限、按钮权限、接口权限 |
| 数据权限 | 本人、本组、本部门、本部门及下级、指定组织、全部 |
| 审计日志 | 登录日志、操作日志、关键业务动作审计，保留 3 个月 |
| 字典参数 | 状态、证据类型、计划类型、规则项 |

### 7.2 P1 业务闭环

| 能力 | 说明 |
| --- | --- |
| 月计划 | 员工提交，负责人必须审批通过后作为当月目标依据 |
| 日计划 | 员工每天提交，负责人可当天或后补审批 |
| 成果 | 原则关联计划，允许临时成果但需说明原因并负责人确认 |
| 证据 | 图片/PDF 可预览，Word/Excel 下载，PDF 预览和导出加水印 |
| 标准 | 交付物模板、验收标准、参考分规则 |
| 台账 | 本人台账、部门台账、资料包导出 |

### 7.3 P2 增强能力

| 能力 | 说明 |
| --- | --- |
| 阿里云 OSS | 文件存储、签名访问、下载鉴权 |
| 阿里云短信 | 初始密码短信、成果确认强认证 |
| 资料包导出 | PDF、Word、Zip |
| 统计看板 | 待审日计划数、逾期未审数、计划闭环率、成果确认率 |
| AI 辅助 | 生成、分析、总结，不做自动审批 |

## 9. 迁移步骤

### 第一步：底座基础

1. 创建 `planning-platform/backend`。
2. 完成认证、用户、部门、组、角色、菜单、权限。
3. 完成审计日志和通用异常。
4. 完成 PC 登录、菜单、路由守卫。
5. 完成 uni-app 登录、首页菜单。

### 第二步：成果计划主链路

1. 月计划表、接口、PC 页面。
2. 日计划表、接口、PC 和 uni-app 页面。
3. 成果表、证据表、接口、PC 和 uni-app 页面。
4. 负责人审批、成果确认、状态流转和审计。

### 第三步：组织权限和台账

1. 部门负责人查看下级所有数据。
2. 项目经理查看本组数据。
3. 员工只能查看本人数据。
4. 台账、统计、资料包导出。

### 第四步：文件、短信、AI

1. 阿里云 OSS。
2. PDF 水印。
3. 阿里云短信强认证。
4. AI 辅助生成、辅助分析、辅助总结。

## 10. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 自研底座前期慢 | 首周可见成果少 | 用 P0/P1 分批交付，先打通登录、权限、日计划 |
| 权限复杂 | 数据越权风险 | 后端统一数据权限拦截，前端隐藏只作为体验 |
| 多端重复开发 | 工期变长 | PC 做管理密集页面，uni-app 只做高频轻操作 |
| 文件和水印复杂 | 首版拖期 | 先 OSS 上传下载，再做预览和水印 |
| AI 范围失控 | 审批责任不清 | AI 只辅助，不自动提交、审批、确认、裁决 |
