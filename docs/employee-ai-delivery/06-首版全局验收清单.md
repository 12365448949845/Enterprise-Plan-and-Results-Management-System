# 首版全局验收清单

本文档承接《成果绩效系统开发文档：员工端》第 13 章，用于首版交付前逐项验收。每一项都必须能通过真实入口、真实路由、真实接口或明确占位反馈验证。

## 1. 员工端主链路验收

| 编号 | 验收项 | 验收方式 | 通过标准 |
| --- | --- | --- | --- |
| AC-01 | 员工可以登录系统 | 使用员工账号登录 PC Web 员工端 | 登录成功后写入 token，进入授权后的员工端入口 |
| AC-02 | 员工可以进入工作台 | 登录后打开 `/employee/dashboard` | 工作台正常加载统计、待办、月计划入口、日计划入口、成果入口、绩效依据入口、申诉入口 |
| AC-03 | 员工可以查看月计划列表 | 从工作台或菜单进入月计划列表 | 列表展示本人月计划，支持月份和状态筛选，不展示他人数据 |
| AC-04 | 员工可以查看日计划日历 | 从工作台或菜单进入日计划页面 | 日历按日期展示本人日计划状态，空日期有可用入口或明确空状态 |
| AC-05 | 员工可以查看月计划详情 | 从月计划列表进入详情 | 详情展示计划条目、交付物、验收标准、状态、审批反馈和成果关联 |
| AC-06 | 员工可以编辑月计划草稿 | 打开草稿或驳回状态月计划编辑页 | 草稿/驳回可编辑并保存，已提交/已通过不可编辑 |
| AC-07 | 员工可以提交月计划审批 | 在月计划编辑页点击提交审批 | 提交成功后状态变为待审批；提交失败时展示失败原因 |
| AC-08 | 员工可以编制日计划 | 打开日计划编制页 | 可选择日期、关联月计划、填写内容、交付物、验收标准、预计工时并保存/提交 |
| AC-09 | 员工可以提交成果文件 | 打开成果提交页 | 可关联计划，填写完成比例，提交成果文件或占位附件信息；提交成功/失败均有反馈 |
| AC-10 | 员工可以查看本人绩效依据 | 打开本人绩效依据页 | 展示本人绩效依据记录、来源计划/成果、确认状态和参考分依据 |
| AC-11 | 员工可以查看申诉记录 | 打开申诉记录页 | 展示本人申诉记录；首版未实现的新申诉/资料包能力有入口和建设中反馈 |
| AC-12 | 领导审批反馈能同步回员工端 | 员工提交计划后，领导端审批通过或驳回，再回员工端查看 | 员工端列表、详情、编辑页状态与领导审批结果一致，并展示反馈意见 |

## 2. 全局行为验收

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| AC-13 | 首版暂不实现的能力必须有入口 | 入口可见、可点击；点击后展示占位页、弹窗或提示，不允许空白页和无响应 |
| AC-14 | 所有提交动作必须有成功或失败反馈 | 登录、保存草稿、提交审批、提交成果、领导审批、驳回等动作均有 loading、成功提示或失败原因 |
| AC-15 | 所有状态必须前后端一致 | 状态值、状态文案、状态颜色、可操作按钮与后端状态流转一致；刷新页面后不回退、不漂移 |

## 3. 验收准入

首版验收前必须至少完成以下检查：

1. `AC-01` 到 `AC-15` 全部通过。
2. 员工端不得只靠前端隐藏控制权限，后端必须校验本人数据范围和状态流转。
3. 领导审批后的状态同步必须覆盖工作台、月计划列表、月计划详情、月计划编辑页。
4. 未实现能力不得出现空白页、死按钮、控制台报错或无提示跳转。
5. 所有提交失败场景必须能看到业务原因或系统错误提示。
