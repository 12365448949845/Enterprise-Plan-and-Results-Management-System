# 员工端 AI 交付总控 Harness

## 1. 文档目标
本 Harness 用于把“员工端所有功能”的开发任务拆成 AI 可独立执行、可并行推进、可回收集成的交付单元。

适用范围：
- 前端先行开发，使用模拟数据跑通真实页面。
- 前端先暴露统一接口调用方式，后续切换到后端真实接口。
- 后端按前端已固化的接口契约补齐控制器、服务、数据表、状态流转和权限校验。
- 文档不仅描述要开发什么，也描述按什么顺序开发、如何联调、如何验收。

## 2. 交付原则
1. 优先复用现有项目技术栈、目录结构、接口封装和 UI 风格。
2. 每个任务单元必须有明确输入、输出、依赖和验收标准。
3. 前端首版不允许空页面；未完成能力也必须保留真实入口和占位反馈。
4. 员工端权限、状态流转、审批反馈、确认记录不能只在前端隐藏，后端必须校验。
5. 所有员工端接口默认只返回当前登录员工本人数据。
6. 所有日期字段必须使用日期/月份控件，不允许普通文本框替代。
7. 文件上传首版只支持 PDF、Word、Zip。
8. mock 数据字段命名必须与后端 DTO 字段保持一致，避免二次返工。
9. 每个 AI 任务完成后必须回填：改动文件、接口影响、验证方式、未完成项。

## 5. AI 任务拆分方式
### 5.1 推荐执行顺序
1. 先固化前端接口类型、mock 数据、路由和页面骨架。
2. 再逐页完成员工端页面，确保都能通过 mock 数据跑通。
3. 然后冻结前端接口契约，输出后端 API 与数据结构说明。
4. 最后开发后端接口、状态流转和权限校验。
5. 联调完成后替换前端 mock 回退逻辑。

### 5.2 推荐并行分组
#### A 组：前端基础组
- A1：员工端接口类型与 mock 数据中心
- A2：员工端路由补齐
- A3：员工端通用状态映射、标签、占位反馈

#### B 组：前端页面组
- B1：登录页
- B2：员工工作台
- B3：月计划详情页
- B4：月计划编辑页
- B5：日计划编制页
- B6：成果提交页
- B7：本人绩效依据页
- B8：申诉记录页

#### C 组：后端组
- C1：员工端数据表与状态设计
- C2：员工端接口控制器与 DTO
- C3：员工端服务层与权限校验
- C4：文件上传与成果版本规则
- C5：审批反馈与确认记录联动

#### D 组：联调验收组
- D1：前后端契约对齐
- D2：状态流转一致性校验
- D3：员工与领导双端互验

## 8. 总体验收口径
1. 所有员工端页面都能从真实入口进入。
2. 前端在无后端完成情况下可通过 mock 数据完整演示主流程。
3. 所有页面接口都已经按统一类型定义暴露。
4. 后端接口严格遵守前端契约字段。
5. 员工仅能操作本人数据。
6. 草稿、提交、通过、驳回、确认、归档等状态前后端一致。
7. 提交、审批、驳回、确认都能落审计/确认记录。
8. 后端接入后，前端只需要切换数据来源，不需要改字段结构。
