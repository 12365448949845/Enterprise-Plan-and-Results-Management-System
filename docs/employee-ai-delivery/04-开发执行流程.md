# 开发执行流程

## 1. 目标
本流程用于指导“员工端前端先行、mock 跑通、接口冻结、后端补齐、联调替换”的完整执行方式，确保多人或多 AI 并行开发时不会失控。

## 2. 总流程
1. 先阅读总控 Harness 和前后端 SDD。
2. 先开发前端，不等待后端完成。
3. 前端用 mock 数据和真实 API 函数并存方式完成页面。
4. 当前端接口字段稳定后，冻结接口契约。
5. 后端按冻结契约落库、写接口、补状态机和权限。
6. 前后端联调后，逐步移除 mock 回退依赖。
7. 完成双端互验和总体验收。

## 3. 前端阶段
### 3.1 阶段目标
让员工端全部页面可访问、可演示、可提交、可反馈，即便后端还未完成也能跑完整个主流程。

### 3.2 执行步骤
1. 扩展 `src/api/employee.ts` 的类型定义。
2. 补齐每个页面对应的 mock 响应结构。
3. 为每个接口提供统一调用函数。
4. 请求真实接口失败时自动回退到 mock 数据。
5. 补齐 `src/router/index.ts` 中员工端路由。
6. 逐页开发员工端页面。
7. 为所有未完成能力保留真实入口和占位反馈。
8. 每做完一页，立刻做一次页面级自验。

### 3.3 页面开发顺序
1. 员工工作台
2. 月计划详情
3. 月计划编辑
4. 日计划编制
5. 成果提交
6. 本人绩效依据
7. 申诉记录
8. 登录页细化

### 3.4 前端自验要求
- 路由可访问
- 有加载态
- 有空状态
- 有错误反馈
- 提交按钮防重复
- 编辑状态和只读状态正确
- mock 数据能覆盖草稿、提交、驳回、通过场景

## 4. 接口冻结阶段
### 4.1 触发条件
当所有页面都能通过 mock 数据演示主流程后，进入接口冻结阶段。

### 4.2 冻结内容
1. 接口路径
2. 请求方法
3. 请求字段名
4. 响应字段名
5. 状态值枚举
6. 分页或列表结构
7. 文件上传参数名

### 4.3 冻结产物
- 更新 `02-前端SDD与Mock接口设计.md`
- 同步更新 `03-后端SDD与接口落地设计.md`
- 禁止后续开发随意改字段名

## 5. 后端阶段
### 5.1 阶段目标
让前端已经调用的员工端接口都能被真实后端接住，并保证数据权限、状态流转、确认记录可落地。

### 5.2 执行步骤
1. 创建或补充员工端核心表。
2. 初始化基础 mock 对应测试数据。
3. 定义 DTO、VO、枚举。
4. 实现查询接口。
5. 实现保存草稿接口。
6. 实现提交审批/提交成果接口。
7. 实现文件上传限制。
8. 实现确认记录写入。
9. 实现员工本人数据权限校验。
10. 补领导审批反馈后的状态同步逻辑。

### 5.3 后端自验要求
- 非本人数据不可访问
- 非法状态变更被拒绝
- 草稿可编辑，已提交不可编辑
- 文件格式限制生效
- 提交、审批、驳回记录可追踪

## 6. 联调阶段
### 6.1 目标
把前端的 mock 回退逐步替换成真实后端返回，保证页面行为不变、字段不变、状态正确。

### 6.2 联调顺序
1. 工作台
2. 月计划详情
3. 月计划编辑
4. 日计划编制
5. 成果提交
6. 绩效依据
7. 申诉记录
8. 员工提交与领导审批反馈互验

### 6.3 联调检查点
| 场景 | 预期 |
| --- | --- |
| 保存月计划草稿 | 前端显示保存成功，后端状态为 draft |
| 提交月计划审批 | 前端状态变 submitted，领导端可见待审批 |
| 领导审批通过 | 员工端展示 approved |
| 领导驳回 | 员工端展示 rejected，允许再次编辑 |
| 再次提交 | 领导端重新出现待审批 |
| 提交成果 | 月计划详情页成果汇总同步更新 |
| 提交日计划 | 工作台日历状态同步更新 |

## 7. AI 分布式协作流程
### 7.1 任务分发原则
1. 每个 AI 只处理一个明确页面或一个明确后端模块。
2. 不允许多个 AI 同时改同一个页面文件，除非先拆分边界。
3. 公共接口文件 `employee.ts` 由一个基础组统一维护。
4. 字段变更必须先更新 SDD，再通知其他任务。

### 7.2 推荐协作顺序
1. 基础组先改 API 文件和路由。
2. 页面组并行做页面。
3. 后端组根据冻结接口并行开发。
4. 联调组最后统一验收。

### 7.3 每个 AI 回填要求
- 改动文件
- 已实现行为
- 未实现项
- 接口影响
- 验证方式
- 风险说明

## 8. 交付完成定义
满足以下条件才算员工端首版完成：
1. 所有页面都有真实入口。
2. 所有页面都能完整显示，不是空白页。
3. 前端在 mock 模式下能完整演示主流程。
4. 后端接口全部接通并字段一致。
5. 员工只能访问本人数据。
6. 提交、驳回、通过、确认都有记录。
7. 工作台、详情、编辑页状态保持一致。
8. 员工与领导之间的计划流转已经互验通过。
9. 通过 `06-首版全局验收清单.md` 中 `AC-01` 到 `AC-15` 全部验收项。
