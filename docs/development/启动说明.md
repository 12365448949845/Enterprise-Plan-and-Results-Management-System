# planning-platform 启动说明

版本：v0.5
日期：2026-07-15

## 端口约定

| 服务 | 默认端口 | 说明 |
| --- | --- | --- |
| 后端 | 48090 | API context-path 为 `/api` |
| PC 管理端 | 5180 | Vue3 + Element Plus |
| MySQL | 3306 | 数据库名 `planning-platform` |
| Redis | 6379 | 默认使用 database 1 |

## 1. 启动 MySQL 和 Redis

已安装 Docker Desktop 时，在项目根目录执行：

```powershell
docker compose -f docker-compose.dev.yml up -d
docker compose -f docker-compose.dev.yml ps
```

开发容器端口只绑定 `127.0.0.1`，不会默认暴露到局域网。需要修改端口或 MySQL 密码时：

```powershell
$env:MYSQL_PORT="3307"
$env:MYSQL_ROOT_PASSWORD="替换为开发环境密码"
$env:REDIS_PORT="6380"
docker compose -f docker-compose.dev.yml up -d
```

如果提示无法连接 Docker API，先启动 Docker Desktop，等状态变为 Running 后重试。

也可以使用本机已有的 MySQL 8 和 Redis 7。默认数据库账号为 `root / 123456`，可通过环境变量覆盖。

## 2. 启动后端

前置条件：JDK 17、Maven、MySQL、Redis。

```powershell
cd backend
mvn.cmd test
mvn.cmd spring-boot:run
```

健康检查：

```text
http://localhost:48090/api/health
```

常用环境变量示例：

```powershell
$env:DB_USERNAME="root"
$env:DB_PASSWORD="123456"
$env:JWT_SECRET="replace-with-a-random-secret-at-least-32-characters"
$env:DEMO_DATA_ENABLED="false"
mvn.cmd spring-boot:run
```

完整的生产环境变量示例见 [backend/.env.example](../../backend/.env.example)。Spring Boot 不会自动读取该文件，部署时需要由 PowerShell、IDE、Docker 或服务器注入环境变量。

## 3. 启动 PC 前端

```powershell
cd web-admin
npm.cmd install
npm.cmd run dev
```

访问：

```text
http://localhost:5180
```

前端默认代理到 `http://localhost:48090`。需要切换后端地址时：

```powershell
$env:VITE_API_TARGET="http://127.0.0.1:48091"
$env:VITE_PORT="5182"
npm.cmd run dev
```

生产构建：

```powershell
npm.cmd run build
```

## 7. 生产环境启动

生产环境使用 `application-prod.yml`，不会自动执行初始化 SQL，也不会创建演示账号和演示业务数据。首次部署前应由运维人员执行并审核 `00-init.sql`。

```powershell
$env:SPRING_PROFILES_ACTIVE="prod"
$env:DB_URL="jdbc:mysql://127.0.0.1:3306/planning-platform?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=true&requireSSL=true"
$env:DB_USERNAME="planning_app"
$env:DB_PASSWORD="替换为数据库强密码"
$env:REDIS_HOST="127.0.0.1"
$env:JWT_SECRET="替换为至少32位的随机密钥"
$env:ADMIN_USERNAME="admin"
$env:ADMIN_PASSWORD="替换为管理员强密码"
$env:UPLOAD_ROOT="D:/planning-platform/data/uploads"
$env:EXPORT_ROOT="D:/planning-platform/data/exports"

cd backend
mvn.cmd clean package
java -jar target/planning-platform-backend-0.1.0-SNAPSHOT.jar
```

`JWT_SECRET` 少于 32 个字符、令牌有效期非法或必填的生产环境变量缺失时，后端会在启动阶段直接失败，不会带着错误配置继续运行。

若启动日志意外出现大量 Spring DEBUG 信息，先检查并清除操作系统中的通用 `DEBUG` 环境变量，再通过 `LOG_LEVEL_ROOT` 和 `LOG_LEVEL_APP` 单独控制日志级别。

## 8. 备份与恢复

MySQL 是业务数据的权威来源，成果附件目录需要和数据库在同一备份周期内保存。建议每天备份数据库和附件，至少保留 7 个日备份和 4 个周备份。

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
mysqldump.exe --host=127.0.0.1 --user=root --password=数据库密码 --single-transaction --routines --triggers --result-file=backups/planning-platform.sql planning-platform
Compress-Archive -Path backend/uploads,backend/exports -DestinationPath backups/planning-platform-files.zip -Force
```

恢复前先停止后端，恢复数据库后再解压附件目录：

```powershell
mysql.exe --host=127.0.0.1 --user=root --password=数据库密码 --execute="source C:/planning-system/代码/planning-platform/backups/planning-platform.sql" planning-platform
Expand-Archive -Path backups/planning-platform-files.zip -DestinationPath . -Force
```

Redis 当前主要承载会话和短期状态，不作为业务台账的唯一存储；开发环境已启用 AOF，生产环境仍建议使用持久化卷并监控磁盘空间。
