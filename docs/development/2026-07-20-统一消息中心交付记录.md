# 统一消息中心交付记录

日期：2026-07-20

## 交付结论

系统已完成全角色统一消息中心。消息严格按 `receiver_id` 查询当前登录人的记录；超级管理员的个人消息也不会混入其他用户待办。

## 后端

- 复用并扩展 `biz_todo`，增加 `message_type` 和 `read_at`，兼容既有待办数据。
- 新增 `/messages/summary`、`/messages`、单条已读和全部已读接口。
- 未读汇总同时返回顶部总数、待办/通知分类数量和侧边栏菜单数量。
- 接入月/周/额外任务审批、日计划点评与风险补审、成果终审、计划调整、申诉、裁决、工作日规则、账号安全和系统配置风险消息。
- 员工撤回已被领导阅读的待办后，向原处理人发送撤回通知；未读原待办直接关闭。
- 裁决评审角色可访问本人被分配的案件，评审加入、移出、回避、意见齐备和裁决结果均生成消息。

## PC Web

- 顶部消息图标显示真实未读数字，点击展示本人全部未读消息。
- 相关侧边栏菜单显示同一消息对应的未读数字，不再使用写死的“待办”标记。
- 点击消息先标记已读，再跳转到对应计划、成果、申诉、裁决或系统管理页面。
- 新增 `/messages` 全部消息页面，支持全部、未读、待办、结果与系统通知筛选，以及单条/全部已读。
- 部门通知待办移除已经迁移给直属领导的“月计划待审批”旧筛选项。

## 数据库兼容

- 新库初始化脚本包含消息字段和索引。
- 旧库由 `SchemaMigration` 幂等增加字段、索引并迁移既有审批结果和导出消息类型。

- 后端主源码和测试源码使用 JDK 17、本机缓存依赖等价编译：通过。
- 消息、审批、系统管理和撤回相关专项测试：72 项通过，0 失败。
