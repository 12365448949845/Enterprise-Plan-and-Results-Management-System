# AI计划与成果检查

## 能力范围

- 月计划、周计划、日计划和额外任务：提交前执行固定规则与千问语义检查。
- 成果：检查附件技术完整性、证据与验收项的对应关系，并给出可解释的完成比例建议区间。
- 员工、直属领导和部门负责人读取同一份已保存报告，AI不参与自动审批、自动驳回或自动改分。

## 判断流程

1. 后端先执行必填项、日期、工时、权重、文件格式、文件大小和文件真实性等确定性规则。
2. 后端组装当前计划、父子计划、部门交付物模板、验收标准和证据文字。
3. 后端把每个可引用字段和证据段落编号为 `SRC_xxxx`；千问只能使用本次来源目录和规则白名单。
4. 千问必须对每一条语义规则返回 `PASS / RISK / UNKNOWN` 逐维度结论，并提供规则编号、来源编号、连续原文和判断理由；模型自评置信度仅保留在审计数据中，不作为页面判断依据。
5. 后端反查规则编号和来源编号，并验证引用原文确实存在。伪造规则、位置或原文的结论会被过滤。
6. 风险严重度由后端按规则类型统一定级，不采用模型自由给出的等级；相同规则的同类问题在不同调用中不会随机变级。
7. 成果只允许按照系统提供的验收项编号逐项判断，模型不能新增、删除或改写验收要求。
8. 成果完成比例不由模型直接决定。模型只返回每个验收项的 `PROVEN / PARTIAL / UNPROVEN / UNKNOWN`，后端按验收项等权计算可解释区间：已证明为100%，部分证明为25%～75%，未证明为0%，无法判断为0%～100%。
9. 当前验收项尚未配置独立权重，因此建议区间只作人工参考；后续增加验收项权重后可按权重计算。
10. 千问未配置、超时或调用失败时，保留系统硬规则结果并允许继续原有人工流程，但页面必须明确显示“AI语义未执行”，不得显示为低风险或检查通过。
11. `PASS` 必须覆盖该维度涉及的全部任务和关键字段；只抽查部分条目或引用不完整时，后端会把结论降级为 `UNKNOWN`。
12. 瞬时超时、限流或上游服务错误会在总时限内自动重试一次；同一内容的并发请求会合并，避免重复扣费和重复报告。
13. 计划内容或检查依据修改后，后端会根据当前内容哈希把旧报告标记为“结果已过期”；页面刷新和领导端查看时也不会把旧结论误当成当前报告。
14. 手动“重新AI检查”会强制生成新报告；提交前使用“确保有效报告”流程，相同内容、模型和提示词版本直接复用，避免重复等待和重复扣费。
15. 发送模型前统一脱敏手机号、邮箱和员工编号；每日检查次数沿用系统管理端模型配置的检查限额，月/周/日/额外任务/成果检查合并计数。

## 千问配置

默认不启用外部模型。取得 API Key 后，在启动后端前配置：

```powershell
$env:AI_ENABLED='true'
$env:QWEN_API_KEY='你的 DashScope API Key'
$env:QWEN_MODEL='qwen3.7-plus'
```

可选配置：

系统管理端存在启用中的模型配置时，以数据库配置为准；总开关、提交前检查开关或供应商设为 `MOCK` 后，环境变量不会绕过管理员设置重新启用外部模型。仅在数据库没有启用中的配置记录时，才使用以下环境变量作为部署级后备配置。

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `QWEN_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | 千问兼容模式地址 |
| `QWEN_ENABLE_THINKING` | `false` | 计划检查默认关闭长推理，避免 `qwen3.7-plus` 响应超时 |
| `QWEN_MAX_OUTPUT_TOKENS` | `1600` | 单次检查最大输出长度；服务端同时执行硬上限，避免长输出拖垮请求 |
| `AI_PROMPT_VERSION` | `v10-calibrated-grounded` | 提示词版本，写入检查记录便于审计；变更后不会复用旧报告 |
| `AI_REQUEST_TIMEOUT_SECONDS` | `60` | 单次检查总时限，包含一次瞬时失败重试 |
| `AI_MAX_EVIDENCE_CHARACTERS` | `30000` | 发送给模型的证据文字上限 |

## 证据处理

- 顶层文件支持 PDF、DOC、DOCX、ZIP，最大 20MB。
- PDF保留页码，Word保留段落/表格位置，ZIP保留内部文件路径。
- ZIP限制文件数量和解压后大小，防止压缩炸弹。
- 文件中的提示词或命令均按不可信数据处理，不能改变模型任务。
- 扫描版PDF若无法提取文字会返回“无法核验”，不会伪造证据结论。

## 数据记录

统一保存到 `biz_ai_review`：

- 业务类型与业务编号
- 业务版本和内容哈希
- 模型、提示词版本、调用状态
- 总体风险、逐维度分析依据、问题明细、证据覆盖和建议完成比例
- 操作人、检查时间和失败原因
- 调用耗时、输入/输出 token、场景成功率和错误分类（同步进入 `ai_call_log`，供系统管理端指标查看）

内容发生变化后哈希随之变化，旧检查结果不会被当作当前提交依据。成果预检查记录只在30分钟内、且内容与文件校验值完全一致时复用。
